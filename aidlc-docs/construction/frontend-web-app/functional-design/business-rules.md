# Business Rules: Frontend Web App

## 入力検証
- **対応ファイル形式**: mp3, wav, m4a のみ。それ以外は拒否しエラー表示
- **最大ファイルサイズ**: 100MB（ブラウザメモリ制約を考慮した仮の上限。レビューで調整可）
- **YouTube URL形式**: `youtube.com/watch?v=<videoId>` または `youtu.be/<videoId>` のみ許可。それ以外は拒否しエラー表示
- **メモの文字数制限**: 最大2000文字（SECURITY-05入力検証に対応。超過分は入力不可、またはエラー表示）

## 低音域強調EQ（FR3）
- gain範囲: -12dB 〜 +12dB
- gain = 0 のとき、EQを通さない元の音と出力が一致する（恒等性）

## スロー再生（FR4）
- 速度範囲: 0.25x 〜 1.0x（音程保持）
- 1.0x超（倍速）はスコープ外（耳コピ用途のため）
- 範囲外の値は範囲内にクランプする

## A-Bループ再生（FR5）
- 制約: `0 <= A < B <= 曲の長さ`、かつ `B - A >= 0.5秒`
- 制約に違反する設定操作は拒否し、直前の有効な状態を保持する

## 音程検出（FR6）
- 検出対象帯域: 約41Hz〜400Hz（ベース音域、Q2回答により限定）
- 帯域外、または検出信頼度(confidence)が閾値（0.8）未満の場合は「検出不能」として扱い、誤った音名を表示しない

## 保存・同期（FR7, FR8）
- **オフラインファースト**（Q1回答）: 保存操作は常にまずローカルストレージに書き込む。ログイン済みかつオンラインの場合のみ、追加でバックエンドへの同期を試みる
- 未ログイン、またはオフラインで同期できなかった場合は`SyncQueueEntry`に保持し、ログイン/オンライン復帰時に送信する
- **競合解決**: 同一`songKey`に対し、ローカルとバックエンドの両方に`SongWorkspaceState`が存在する場合、`updatedAt`が新しい方を正とする（Last-Write-Wins）。複雑なマージは行わない
- `SyncQueueEntry`は`songKey`ごとに最新の1件のみ保持する（同じ曲に対する古いキュー項目は新しい変更で上書きされる）

## 再生機能の提供範囲（FR2, Application Design準拠）
- ローカルファイル入力時: EQ・スロー再生・音程表示・波形表示・サンプル精度ループを提供（`PlaybackCapabilities`で全てtrue、`loopPrecision: "sample"`）
- YouTube入力時: 再生速度変更（YouTube標準機能）と簡易ループのみ提供（`loopPrecision: "approximate"`）。EQ・音程表示・波形表示は提供しない旨をUIに明示する
