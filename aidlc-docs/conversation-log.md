## ワークフロープランニング／アプリケーション設計／ユニット分割

- Application Design: ローカル再生とYouTube再生は共通インターフェース（Strategyパターン）、バックエンドは単一サービスで構成することを確認して決定。
- Units Generation: Frontend Web AppとBackend Sync APIを**2つの独立したUnit**に分離し、**モノレポ**構成（`frontend/`, `backend/`）にすることを確認して決定。

## Unit 1: Frontend Web App の設計・実装

- Functional Design: オフラインファースト保存（ローカル優先、ログイン・オンライン時のみクラウド同期）、ピッチ検出はベース音域（約41〜400Hz）に限定することを決定。
- NFR Requirements: 技術スタックについて

  **User**: ウェブで動かすにあたってちょうどいい方法を検討したいから、色々教えて。

  → フレームワーク（React/Vue/Svelte/Vanilla）、TypeScript有無、ピッチ検出の実装方法（既存ライブラリ vs 自前実装）について、それぞれのトレードオフを説明。結果: **React + TypeScript + pitchy（既存ライブラリ）**に決定。

- NFR Design: リトライの指数バックオフ、`requestAnimationFrame`による間引きポーリングなどを決定（質問なしで妥当な方針を提示しレビューしてもらう形）。
- Infrastructure Design: ホスティング先について

  → **Vercel**（無料枠、Git連携、カスタムヘッダー設定が可能）に決定。

- Code Generation: 14ステップの計画を承認後、実際にコードを生成。React/TypeScript/Viteアプリとして、音声処理エンジン（EQ、タイムストレッチ、ピッチ検出、波形表示、ループ編集）、UIコンポーネント、テスト（fast-checkによるProperty-Based Testing含む）を実装。型チェック・テスト（48/48）・ビルド・`npm audit`（0件）を確認。依存バージョンに既知の脆弱性が見つかったため、React 19/Vite 8/Vitest 5系列の最新版に更新。
