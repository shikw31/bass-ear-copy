# Requirements: 耳コピ補助アプリ（Bass Ear-Copy Assistant）

## Intent Analysis Summary

- **User Request**: 「ベースをやっていて、耳コピでコピーバンドの練習をしたい。ある程度は聞こえるけど時間もないので、耳コピを補助するアプリを作りたい」
- **Request Type**: New Project (Greenfield)
- **Scope Estimate**: Multiple Components（音声処理エンジン、YouTube埋め込み連携、ローカル音声ファイル処理、クラウド同期、認証、可視化UI）
- **Complexity Estimate**: Moderate〜Complex（ブラウザ上でのリアルタイム音声DSP処理、ピッチ検出、クラウド同期、認証を含む）
- **Requirements Depth**: Standard

## Background / Context

ベースを担当しており、コピーバンドの練習のために楽曲を耳コピしている。ある程度は聞き取れるが時間的制約があるため、耳コピを効率化する補助アプリを作りたい。個人用ツール（単独ユーザー）として、自宅PCとスタジオでのスマホの両方で使う想定。

## Functional Requirements

### FR1: プラットフォーム
- Webアプリとして提供し、PC・スマホの両方のブラウザからアクセス・利用できること。

### FR2: 音源入力（ハイブリッド方式）
- **FR2.1 ローカル音声ファイル**: mp3/wav/m4a等の音声ファイルをアップロードして再生・処理できること。音声処理系の本格機能（FR3〜FR6）はこの入力経路でのみ提供する。
- **FR2.2 YouTube埋め込み**: YouTube動画のURLを指定し、公式IFrame Player API経由で埋め込み再生できること。YouTube標準機能である再生速度変更（0.25x〜2x、音程保持）と、再生位置シークによる簡易A-Bループ（サンプル精度ではなく、数百ms程度の誤差を許容）を提供する。
- **FR2.3 対象外（規約上の制約）**: YouTube/Spotifyからの音声データの抽出・ダウンロード・再保存は実装しない（利用規約違反のため）。
- **FR2.4 Spotify対応は本バージョンのスコープ外**: Spotify Web Playback SDKは再生速度変更機能自体を提供しておらず、生音声データへのアクセスも規約上不可のため、現時点では対応しない。将来的に「再生位置の記録・共有」程度の軽量連携を追加検討する余地はあるが、v1には含めない。
  - **レビュー時確認事項**: この除外方針でよいか、要件レビュー時に確認してください。

### FR3: 低音域強調EQ（MVP最優先機能）
- ローカル音声ファイル再生時、ベースの帯域（目安: 40Hz〜250Hz程度、調整可能）を強調するEQ/フィルタをリアルタイムに適用できること。
- EQの強調度（gain）をユーザーが調整できること。

### FR4: スロー再生（ピッチ保持）
- ローカル音声ファイルの再生速度を、音程を変えずに落とせること（タイムストレッチ）。

### FR5: A-Bループ再生
- ローカル音声ファイルについては、指定した区間をサンプル精度でループ再生できること。
- YouTube埋め込みについては、シークベースの簡易ループ（FR2.2参照）を提供すること。

### FR6: 音程・波形の可視化
- **FR6.1**: ローカル音声ファイル再生中、リアルタイムに基音の音名（例: E2, A2）と周波数(Hz)を表示する簡易チューナー的機能を提供すること。
- **FR6.2**: 波形表示および/またはスペクトログラム表示により、音の変化を視覚的に確認できること。

### FR7: 曲ごとのデータ保存（2026-10-25改訂: ローカル保存のみに変更）
- 曲（アップロードしたファイル、またはYouTube URL）ごとに、ループ区間（A/Bポイント）とメモ（TAB・運指メモ等のテキスト）を保存・再利用できること。
- 保存先は使用中の端末のブラウザ（ローカルストレージ）のみ。クラウド同期は行わない（下記FR8の変更を参照）。

### FR8: クラウド同期と認証 — **削除（2026-10-25改訂）**
~~ユーザー個人の認証（ログイン）機能を提供し、FR7で保存したデータが本人の複数端末間で同期されること~~

**変更理由**: ログイン・ログアウト等の認証機能は不要とし、純粋なWebアプリ（バックエンドなし）として提供してほしいとの要望（2026-10-25）。これにより、自宅PCとスタジオのスマホ間でのループ区間・メモの自動同期はできなくなる（各端末でローカルに保存されるのみ）ことをユーザーに確認し、合意済み。
- 既に実装済みのBackend Sync API（Unit 2、`backend/`）はリポジトリに残すが、フロントエンドからは利用しない（未使用のまま保持、将来の復活に備える）。

## Non-Functional Requirements

### NFR1: パフォーマンス
- EQ適用・ピッチ検出・タイムストレッチ処理は、ブラウザ上でリアルタイムに（知覚できる遅延なく）動作すること。

### NFR2: 対応ブラウザ
- Web Audio APIをサポートする主要ブラウザ（Chrome, Safari, Firefox, Edge）のデスクトップ版・モバイル版で動作すること。

### NFR3: ユーザビリティ
- スタジオなど練習の場で素早く使えるよう、ファイル読み込み/URL指定からループ開始までの操作が最小限であること。
- モバイル（タッチ操作）に適したUIであること。

### NFR4: データプライバシー
- アップロードした音声ファイルや個人のメモは、使用中の端末のブラウザ内にのみ保存され、外部に送信・共有・公開されないこと（2026-10-25改訂: アカウント概念を削除したため「本人のブラウザ内」に変更）。
- （注記）ユーザーが自分でアップロードする音声ファイルの著作権上の取り扱いはユーザー自身の責任とする。

### NFR5: 法令・規約順守
- YouTube/Spotifyの利用規約に違反する音声抽出・ダウンロード機能は実装しない（FR2.3参照）。

### NFR6: セキュリティ（Security Baseline拡張: 有効化）
- Security Baseline拡張の全ルール（SECURITY-01〜15）は引き続き適用する。
- **2026-10-25改訂**: FR8（認証・クラウド同期）削除に伴い、認証関連ルール（SECURITY-12等）やサーバー間のアクセス制御（SECURITY-08の一部）はこのフロントエンド単体構成ではN/Aとなる。入力検証（SECURITY-05）、依存関係管理（SECURITY-10）等、フロントエンド単体に適用可能なルールは引き続き有効。

### NFR7: テスト（Property-Based Testing拡張: Partial）
- 音声処理の純関数部分（ピッチ検出アルゴリズム、EQ係数計算、タイムストレッチのコア処理等）について、PBT-02（ラウンドトリップ）、PBT-03（不変条件）、PBT-07（ジェネレータ品質）、PBT-08（シュリンク・再現性）、PBT-09（フレームワーク選定）を以降のフェーズで強制適用する。他のPBTルールはアドバイザリ（非ブロッキング）とする。

### NFR8: レジリエンシー拡張
- 個人用ツールのため、Resiliency Baseline拡張は適用しない（スキップ）。

## Summary

個人のベース練習・耳コピ支援を目的としたWebアプリ。ローカル音声ファイル入力で低音域EQ・スロー再生・精密A-Bループ・音程/波形可視化を提供し、YouTube埋め込みで手軽な速度変更・簡易ループにも対応するハイブリッド構成。曲ごとのループ/メモはブラウザのローカルストレージに保存（2026-10-25改訂: 認証・クラウド同期は削除。端末間同期はなし）。セキュリティ拡張は有効（適用範囲は縮小）、レジリエンシー拡張は無効、PBTはPartial適用。

## 変更履歴

### 2026-10-25: 認証・クラウド同期（FR8）を削除
- **変更内容**: ログイン・ログアウト機能、およびバックエンド（Backend Sync API, Unit 2）との連携を削除。フロントエンド単体（ブラウザのローカルストレージのみ）で動作する構成に変更
- **理由**: 「ただウェブで動かすだけでよくて、ログイン・ログアウトとかもいらない」というユーザー要望
- **影響**: 自宅PCとスタジオのスマホ間でのループ区間・メモの自動同期ができなくなる（各端末で個別にローカル保存）。ユーザーはこのトレードオフを確認し合意済み
- **既存のUnit 2（`backend/`）**: 削除せずリポジトリに残すが、フロントエンドからは呼び出さない（未使用）
- **実装**: `frontend/src/api/`, `AuthBar.tsx`, `syncOrchestrationService.ts`, `retryQueueManager.ts`, `networkStatusMonitor.ts`, `mergeLastWriteWins.ts`を削除。`SongWorkspace`に`loadLocal()`/`saveLocal()`を追加し、ローカルストレージへの直接読み書きに簡素化
